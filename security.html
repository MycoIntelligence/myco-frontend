Security by architecture

Your code stays
in your environment.

Myco is engineered so source code never leaves the environment you authorize. It is never retained after analysis.

SOURCE CODE
STAYS PUT
01 · PROCESSING BOUNDARY

Code does not leave.

Myco performs analysis within your environment. Your source code is not sent outside of that boundary.

02 · DATA LIFECYCLE

Nothing to retain.

Source code is used only for the active analysis, then discarded. Myco does not retain a copy of your code.

03 · ACCESS MODEL

Read-only by design.

Myco observes authorized repository context. It does not write to source code or push changes to your repository.

The processing boundary

Analysis happens close to the code, not somewhere else.

The product is designed around a narrow principle: bring the reasoning to the authorized environment, rather than moving source code into a separate data store.
